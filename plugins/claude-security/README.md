# claude-security

按需深度安全扫描：对**已经存在**的代码做多 agent 扫描——包括从来不是 AI 写的、历史遗留的那些——
每条发现经独立复核后才进报告；选定的发现可以变成补丁，但补丁由你自己应用。

它是三层代码安全中的**存量清查**那一层。三层的分工按「谁能看见哪些代码」划分：

| 层 | 触发 | 看得见的代码 |
| --- | --- | --- |
| `security-guidance` 插件 | 自动，写码过程中 | 只有增量：本次写入、本轮改动、Claude 自己的提交 |
| **`claude-security`（本插件）** | 手动，你发起 | **整个仓库 / 任意区间：分支 diff、单个提交、无版本控制的目录** |
| 内置 `/security-review` | 手动，单次 | 当前分支相对基线分支的全部改动 |

自动层只看得见 AI 自己动过的东西；清查存量是它结构上做不到的事——这就是本插件存在的理由。

## 安装后你会得到

- `/claude-security:scan` — 选择扫描范围后发起扫描
- `/claude-security:patch` — 把报告里选定的发现变成补丁

不装任何东西的 `git diff` 级自查，用内置的 `/security-review`。

## 扫描做了什么

1. **先量后问**（只读）：统计仓库类型、文件数、基线分支、本分支独有提交数、未提交改动，然后
   **把可选的扫描范围与各自的文件数、相对成本摆出来**。你不选，它不动任何东西。
   - 整库 / 聚焦某个目录 / 只扫本分支相对基线的 diff（有独有提交时才出现）/ 单个提交
   - 工作区有未提交改动时会明说：diff 类范围只覆盖已提交内容
2. **建报告目录**：`WAVE-SECURITY-<时间戳>/`，并写入自带忽略规则（见下）。
3. **三段式多 agent 扫描**，顺序固定、不可跳：
   - **梳理架构 + 建威胁模型**（1 个 agent）：入口点、信任边界、敏感数据、攻击者会怎么打——这是
     后续所有狩猎者的作战简报。
   - **并行狩猎**（每区域 1 个 agent，上限 6）：每个区域一个狩猎者，只报能说清可达路径的问题。
   - **逐条独立复核**（每条发现 1 次判定）：复核者拿不到发现者的推理与置信度，只拿发现和代码，
     自己读调用方与校验点，给出 `confirmed / rejected / uncertain`。**只有 `confirmed` 进报告**，
     其余进否决清单并附理由，不计入发现数。
4. **落三份产物**（见下），并在对话里汇报范围、修订版本、各级严重度数量、报告路径。

## 产物目录

```
WAVE-SECURITY-<yyyyMMdd-HHmmss>/
├── .gitignore          # 内容为 `*`：整个目录不进 git add
├── report.md           # 人读：范围与修订版本、发现表、逐条详述、否决清单、两条口径说明
├── findings.json       # 机器可读：scan 元信息 + findings[] + rejected[]
├── results.sarif       # SARIF 2.1.0，按 CWE 归类，可直接喂给支持代码扫描的平台
└── patches/            # 只有 /claude-security:patch 会写；没跑过补丁就没有这个目录
```

- 目录名带时间戳，所以两次扫描各留一份，不会互相覆盖。
- 目录里的 `.gitignore` 用 `*` 把自己整个排除在版本控制之外——普通 `git add` 不会误收它。
  **要归档报告，显式删掉那条忽略规则即可。**
- 报告里的每条发现都带 `revision`：扫描时的 commit、`git hash-object` 得到的 blob sha（不在版本
  控制下则记 size/mtime）。这让报告能归因到它描述的确切代码。

## 补丁由谁拍板

`/claude-security:patch`（可跟 `F1 F3` 指定发现，默认让你多选，一次最多 5 条）：

1. **先校验报告没过期**：逐条比对文件当前内容与报告记录的 blob sha；不一致就跳过该发现并提示重新
   扫描，而不是照着过期报告改写。
2. **在仓库临时副本里起草**（`/tmp/WAVE-SECURITY-PATCH-<ts>-F<n>/`），你的源文件保持不动。
3. **独立复核者检查**：跑项目测试（读到测试命令时），并独立读 diff 判断三件事——修好了该发现、没
   引入新漏洞、其余行为不变。三点不能同时确认就**不产出补丁**，改为给一段说明。
4. **产出**：`patches/F<n>.patch` + `patches/F<n>.md`（改动说明、验证方式、残余风险、如何应用）。
   **补丁从不自动应用**——`git apply <路径>` 由你执行。临时副本用完即清。

## 打印什么、不打印什么

- 扫描**只读**：不改你的源文件、不跑被审计的代码、不动 git 状态；唯一的写入在自己的报告目录里。
- 补丁阶段的起草发生在**子代理**里、且只在临时副本（`/tmp/WAVE-SECURITY-PATCH-*`）中；你的源文件自始
  至终不在改动范围内。命令的 `allowed-tools` 已经把"报告目录内的写入"登记为免确认；子代理在临时副本
  里的编辑会走一次权限确认（想全程免确认，在 `permissions.allow` 里加一条
  `Edit(**/WAVE-SECURITY-PATCH-*/**)`）。
- 扫描**不阻塞**任何动作：它把发现交给报告和你的判断，不拦提交、不拦合并。

## 能力边界（说在前面）

- 扫描是**随机的**：同一份代码扫两次，发现的集合可以不同。它的价值来自定期执行，不是可复现。
- 可能**漏报**。它是纵深防御里的若干层之一，不是完整方案；也不能替代你已有的 SAST / 依赖扫描——
  它推理的是代码语义，与确定性检查互补。
- 自动层看不见你在自己终端里做的改动；本层的 diff 范围也只覆盖**已提交**内容。
- 面向**用户自有或已获授权的代码**，不用于扫描第三方代码。
- 报告与发现会进入 AI 的上下文——含代码片段。按公司对模型输入的规定处理敏感代码。

## 卸载

在插件市场卸载即可，本插件不留常驻进程、不写会话外状态。已产出的 `WAVE-SECURITY-*` 目录与
`/tmp/WAVE-SECURITY-PATCH-*` 临时副本可以整个删掉；临时副本正常情况下在当次补丁流程结束时已清理。
