# 讲解 Ralph 循环

用户想知道这个插件是干什么用的。**把下面这几段讲给他听**，不要启动循环、不要动他
项目里的任何文件。

## 一句话

把同一段 prompt 一轮一轮喂回**同一个会话**：每轮都在上一轮留下的文件和 git 历史
上继续干，直到模型自己输出完成标记，或者到达轮次上限。

## 原形与原理

这叫 Ralph 技术，出自 Geoffrey Huntley（https://ghuntley.com/ralph/），原形就是一行 shell：

```bash
while :; do
  cat PROMPT.md | <agent> --continue
done
```

同一段 prompt 反复喂，脚本本身不判断进度。所谓「自指」，指的是模型每轮都能在
**文件系统与 git 历史里看到自己上一轮的成果**，而不是把上一轮的输出回灌给自己。

每一轮做的都是同一件事：

1. 收到**一模一样**的 prompt
2. 干活，改文件
3. 想结束回合
4. Stop hook 拦下，把同一段 prompt 再喂回去
5. 下一轮先看到上一轮留下的文件和 git 历史
6. 在它之上继续改，直到完成标准达成

所以它的取向是「失败可预测」：同样的 prompt、同样的判据，跑坏了能靠改 prompt 系统性
改进，而不是每次都要人临场指挥。

## 命令

### `/ralph-loop:ralph-loop <prompt> [选项]`

在当前会话里开一个循环。例子：

```
/ralph-loop:ralph-loop 重构缓存层 --max-iterations 20
/ralph-loop:ralph-loop 补齐测试 --completion-promise "TESTS COMPLETE"
```

选项：

- `--max-iterations N`：**总共 N 轮（含首个回合）**，也就是最多喂回 N-1 次；`0` 或不给 = 不限轮
- `--completion-promise TEXT`：完成标记，模型在回复里输出 `<promise>TEXT</promise>` 才算完成

开起来之后：

1. 写状态文件 `.wave/ralph-loop.local.md`
2. **第 1 轮就是发起的那个回合**，模型当场开始干活，不会先回一句「已就绪」
3. 回合想结束时 Stop hook 拦下，同一段 prompt 再喂回去
4. 一直喂到命中完成标记、或到达轮次上限

### `/ralph-loop:cancel-ralph`

删掉状态文件，当前回合结束后不再喂回。没有任何循环时它会直接说「没有正在跑的循环」。

### `/ralph-loop:help`

就是你现在在做的事——只讲解，不启动。

## 关键概念

**完成标记**：模型必须输出

```
<promise>TASK COMPLETE</promise>
```

这样一段标签，Stop hook 才会放它走。没设标记又没设 `--max-iterations` ⇒ 无限循环。
标记是逐字比较的（只归一空白），要跟 `--completion-promise` 写的一模一样。

**自指**：不是「模型跟自己对话」，而是「同一段 prompt 反复来 + 成果留在文件里 +
每轮都能看到上一轮的尝试」。

## 什么活适合交给它

- **成功标准明确、能自动验证**：测试全绿、lint 干净、构建通过、某个脚本输出符合预期
- **允许重复劳动**：同一段指令反复执行，每轮的产出落到文件里，下一轮在它之上继续
- 典型：把失败的测试逐个修绿、按清单把 N 个文件改成同一种写法、把迁移脚本一个个跑通

**别用在这些地方**：

- 需求模糊、需要人拍板——循环不会让模糊变清晰，只会把模糊重复 N 遍
- 一次性问答、纯探索——没有完成标准就没有终点
- 需要中途审阅的改动——它闷头跑，中途不听指挥
- 不可逆操作（删数据、推远端、发版）——每轮都会再执行一次

## 跑之前要提醒他的两件事

- **循环管不到权限门**：它只负责把 prompt 喂回去，模型这一轮要调的工具照样逐次弹窗。
  默认 / `plan` 模式下跑长循环，他会守在一堆权限窗前面。想真无人值守，启动时换
  `acceptEdits`（自动接受文件编辑）或 `bypassPermissions`（全放行，慎用）；`dontAsk`
  并不会更好——它不弹窗，但把没被规则放行的工具直接自动拒绝，循环会在同一处反复失败。
- **把 `.wave/` 加进 `.gitignore`**：循环期间 `.wave/ralph-loop.local.md` 每轮都在改，
  不 ignore 会一直挂在 `git status` 里，还容易被顺手 `git add` 进去。

## 收尾

参数细节（完成标记含空格要加引号、等号形式不支持、状态文件路径）让他敲
`/ralph-loop:ralph-loop --help`——那是从脚本里直接打出来的用法，**别在这里凭印象复述**
（尤其别自己发明不存在的参数写法）。

讲完用一两句话问他手上有没有符合条件的活、要不要现在开一个循环；**要不要开由他决定**，
不要替他启动。
